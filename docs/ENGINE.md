# 引擎与构建边界

只适用于 README 所列精确源文件。CPU 地址与文件偏移不同。此 LoROM 的文件偏移为 `bank * 0x8000 + (address & 0x7fff)`，下面主文本合同要求地址在 `$8000..$FFFF`。

| 消费者/资源 | 已定位入口 |
|---|---|
| 48 组三字节文本目录 | 文件 `0x5277` / CPU `00:D277` |
| 正文循环 / getter | `01:85A7` / `01:8B3C` |
| 正文当前指针 | DP `$AD/$AE/$AF` |
| 原生 FF handler | `01:8876`；运行 FF 结束观察点 `01:88A7` |
| 菜单 renderer / getter | `00:C804` / `00:CD9E` |
| 菜单当前指针 | DP `$1A/$1B/$1C` |
| 原字库两个页面起点 | 文件 `0x80856` / `0x81856` |
| 标题压缩源 | `21:BA94`，指针字段文件 `0x8000C` 原像 `94 BA 21` |

主文本 F3..FF 的语法以公开 control-contracts 为准。F6 子调用、F7 随机、F8/F9 条件与绝对转移、FF 返回需保留原参数；条件位按 MSB-first 读取。低级菜单另有 F4 模式状态和调用方继承状态，原文看起来像假名不意味着可以在任意脚本位置插中文字节。

R1 从 1.5 MiB 扩到 2 MiB：新正文分配于 CPU bank `30..3B`，扩展字库 `3C..3E`，钩子 `3F:8000`，查找表 `3F:8800`。标题新资源位于文件 `0x1D0000` / CPU `3A:8000`；标题只改解压图形中的 `[0x1000,0x1400)` 三个菜单标签，原 Logo 保留。

构建器以连通组件分配同 bank 的文本，再补内部 word 目标、显式续接及动态名称入口；不是把整句原地覆盖。每次写源区域都核对前像，分配区检查重叠和边界。最终回读再检查原字节、控制参数、译文、查找表和实际 bank。

1,817 个新增字形为 Fusion Pixel 的 12px 点阵装入原生 12×16 设计格；原单字节字符继续复用原字形。字形编码、页面指针与原生行缓冲消费者需同时一致。模型只覆盖钩子所需指令和 ABI，不模拟实际 PPU 时序。

本轮公开版将标题生成改为从自备源文件解压，并核对已冻结源像素哈希，消除历史 VRAM 转储依赖；CPU 模型随仓库提供，Mesen 路径由 `MESEN_EXE` 指定。公开构建 manifest 中标题证据字段因而与历史原始 manifest 不同；目标 ROM 和 BPS 应保持字节一致。历史运行证据不是本轮重跑结果。
